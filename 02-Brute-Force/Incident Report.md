# Incident Report — Windows Brute-Force Detection

## Incident Information

| Field              | Details                            |
| ------------------ | ---------------------------------- |
| **Incident Title** | Windows Brute-Force Detection      |
| **Detection**      | Multiple Failed Windows Logons     |
| **SIEM**           | Splunk Enterprise                  |
| **Host**           | `Kakarot`                          |
| **Source IP**      | `127.0.0.1`                        |
| **Primary Event**  | Windows Event ID `4625`            |
| **Related Event**  | Windows Event ID `4624`            |
| **Logon Type**     | `2` — Interactive                  |
| **Severity**       | Medium (Configured in Splunk)      |
| **Impact**         | Low — Lab Simulation               |
| **Classification** | Benign / Controlled Lab Simulation |
| **Status**         | Closed                             |
| **Environment**    | Personal Security Lab              |

---

## Summary

A Splunk detection identified multiple failed Windows authentication attempts occurring within a short time period.

The activity was intentionally generated on the analyst's Windows 11 lab machine to test a brute-force detection rule and Splunk alerting workflow.

No unauthorized system or account was targeted.

---

## Detection

The detection identifies three or more Windows Event ID `4625` events within a one-minute window.

The detection successfully identified multiple controlled test sequences.

The final validation test at `17:50:00` produced:

* **4 failed logon attempts**
* **Source IP:** `127.0.0.1`
* **Logon Type:** `2`
* **Detection window:** 1 minute

---

## Investigation Findings

The investigation determined that:

1. The failed authentication events were Windows Event ID `4625`.
2. The activity originated from `127.0.0.1`, the local Windows system.
3. The observed Logon Type was `2`, representing an interactive logon.
4. Authentication failure status values were consistently observed: `0xc000006d` and `0xc0000380`.
5. Successful authentication events occurred after controlled failed-login sequences.
6. The activity was intentionally generated by the analyst during testing.

---

## Alert Response

The scheduled Splunk alert:

**Windows Brute Force - Multiple Failed Logons**

successfully triggered and appeared under:

**Splunk → Activity → Triggered Alerts**

The alert was configured with:

* **Severity:** Medium
* **Schedule:** Every minute
* **Search Window:** Last 5 minutes
* **Mode:** Digest
* **Trigger Condition:** Number of results greater than 0

This confirmed that the detection logic and alerting workflow were functioning as expected.

---

## MITRE ATT&CK

**T1110 — Brute Force**

The detection is associated with the Brute Force technique because it identifies repeated authentication failures.

The mapping represents the behavior being detected and does not indicate that the lab activity was a real attack.

---

## Root Cause

The authentication failures were intentionally generated by the analyst by entering incorrect credentials on the Windows login interface.

Therefore, the root cause was:

**Controlled security testing.**

---

## Impact

No security impact was identified.

The activity occurred entirely within the analyst's personal Windows security lab.

No external systems were targeted.

No evidence of unauthorized access was identified during the investigation.

---

## Response

Because the activity was a controlled lab simulation:

* No account was disabled.
* No system was isolated.
* No credentials were reset.
* No external IP was blocked.
* No escalation was required.

The alert was documented as a successful detection test.

---

## Final Disposition

**Classification:** Benign / Controlled Lab Simulation

**Status:** Closed

The detection successfully identified the simulated authentication activity, the alert triggered correctly, and the investigation confirmed that the activity was intentionally generated for security testing.

---

## Lessons Learned

This project demonstrated the importance of:

* Monitoring Windows authentication events.
* Understanding Windows Event ID `4625`.
* Extracting fields from raw SIEM events.
* Detecting repeated authentication failures.
* Correlating failed and successful authentication events.
* Configuring SIEM alerts.
* Investigating source IP addresses and Logon Types.
* Distinguishing a detection from a confirmed security incident.
* Documenting investigation findings clearly.
